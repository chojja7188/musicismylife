# ADR 0007: MP4 녹화는 중간 분할 없이 종료 시 확정

- 상태: 채택 · 2026-11-17
- [ADR 0004](0004-recording-format.md)의 MP4 우선 형식은 유지하고 녹화 시작 방식을 보완한다.

## 맥락

사용자가 녹화 파일을 이메일로 갤럭시에 옮겼을 때 갤러리는 3초로 표시하고, 3초 이후 탐색은 불가능하지만 끝까지 재생은 됐다.

제공된 파일을 로컬에서 분석한 결과 실제 영상은 54.604633초였다. 그러나 `mvhd`의 전체 길이는 0, `tkhd`의 트랙 길이는 3.366초였으며 탐색 색인 `mfra`/`sidx`도 없었다. 영상·음성 데이터 자체는 끝까지 있었다. 이메일 전송 중 잘렸다는 근거는 없다.

기존 `recorder.start(1000)`은 Chrome MP4를 중간 출력하는 라이브 모드로 만들었다. [Chromium 공식 구현](https://chromium.googlesource.com/chromium/src/+/main/media/muxers/mp4_muxer_delegate.cc)의 `FlushFragment()`는 라이브 모드를 켜며, 이 모드에서는 전체 영화 길이를 채우지 않고 마지막 탐색 색인도 쓰지 않는다. 파일을 완성하기 전에 첫 구간의 트랙 길이로 헤더가 확정되는 현상과 일치한다.

## 결정

- 다운로드용 녹화는 `recorder.start()`로 시작하고 `stop()`에서 파일을 완성한다. MP4를 녹화하는 동안 `timeslice`나 `requestData()`를 사용하지 않는다.
- 형식 우선순위·화질·프레임률·총시간·오디오 구성은 바꾸지 않는다. 외부 라이브러리나 빌드 의존성을 추가하지 않는다.
- `tests/recording.cjs`는 임시 페이지·서버·Chrome 프로필로 실제 녹화를 수행한다. 전체 `mvhd`/`tkhd` 길이, 여러 구간의 `tfra` 색인, 브라우저에서 5초 지점으로 탐색을 검사한다.
- 이미 만들어진 문제 파일은 별도 사본으로 무손실 재포장한다. 원본을 덮어쓰지 않는다. 복구 예:

```bash
ffmpeg -i input.mp4 -map 0:v:0 -map 0:a:0 -c copy -movflags +faststart fixed.mp4
```

## 결과와 한계

회귀 검사는 기존 코드에서는 전체 길이 헤더 검사에 실패하고, 수정 후 전체 길이·색인·5초 탐색에 통과했다. 중간 분할을 없애도 출력은 여전히 조각형 MP4일 수 있으므로 “일반 비분할 MP4로 변환했다”고 설명하지 않는다.

제공된 기존 파일은 FFmpeg로 일반 MP4 사본을 만들고 54.604633초 길이·40초 지점 프레임 추출을 확인했다. `-c copy`로 복사한 영상·음성 각각의 SHA-256 스트림 해시가 원본과 같았다.

갤럭시 갤러리 실기에서의 최종 표시·탐색은 사용자 확인이 필요하다. WebM 대체 형식은 이 MP4 색인 검사 대상이 아니다. 녹화 데이터를 종료 때까지 브라우저에 보관하므로 긴 영상은 메모리 부담이 커질 수 있다. 기본 용도는 1분 이내다.
